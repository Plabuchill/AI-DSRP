# Requirements — AI-DSRP

## 1. ภาพรวม

เอกสารนี้เป็นฉบับทางการครั้งแรกที่รวบรวม pain point ของทีมงานจริงที่กระจายอยู่ใน [[../../../ROADMAP.md|ROADMAP.md]] (คำนำ) และ [[FEATURE-LIST.md|FEATURE-LIST.md]] (บรรทัด "Requirement ต้นทาง" ต่อโมดูล) มารวมไว้ในที่เดียว เพื่อเป็นต้นน้ำของความต้องการก่อนแตกเป็น backlog/feature-list ต่อไป ครอบคลุมกลุ่มผู้ใช้งาน 5 กลุ่ม ได้แก่ เจ้าหน้าที่โรงพยาบาล/เทศบาล, ทีมสอบสวนโรค, ทีมควบคุมโรค/ทีมพ่น, ทีม อสม. และผู้บริหาร/เจ้าหน้าที่เฝ้าระวัง

รอบนี้ (2026-09-06) ครอบคลุมเฉพาะหัวข้อ Pain Point เท่านั้น — ยังไม่รวม User Story, Business Rule แยกหัวข้อ หรือ Scope in/out (จะเพิ่มในรอบถัดไปเมื่อ Build Plan ระบุให้ทำ)

## 2. Pain Point

### `PAIN-HOSPITAL-01` — ข้อมูลรายงานโรคยังอยู่ในรูป PDF/JPEG

| หัวข้อ | รายละเอียด |
|---|---|
| กลุ่มผู้ใช้ที่เจอ | เจ้าหน้าที่โรงพยาบาล/เทศบาล |
| ปัญหา | ข้อมูลรายงานโรคจากโรงพยาบาลอยู่ในรูป PDF/JPEG จำนวนมาก ต้องแปลงเป็นข้อมูลใช้งานได้เร็วขึ้น |
| ผลกระทบ | เจ้าหน้าที่ต้องคีย์ข้อมูลด้วยมือจากเอกสารสแกน ทำให้ล่าช้าในการส่งต่อข้อมูลไปยังทีมสอบสวนโรค เสี่ยงต่อการรายงานเคสไม่ทันเวลา |
| แหล่งที่มา | รวบรวมจาก ROADMAP.md (คำนำ) + FEATURE-LIST.md บรรทัด Requirement ต้นทาง ของ FEAT-INTAKE (`prototypes/v1/case-intake.html`) |

### `PAIN-INVESTIGATION-01` — ต้องการ AI ช่วยเชื่อมโยงเคส/ร่างรายงาน และระบบเก็บ รง.506

| หัวข้อ | รายละเอียด |
|---|---|
| กลุ่มผู้ใช้ที่เจอ | ทีมสอบสวนโรค |
| ปัญหา | ทีมสอบสวนโรคต้องการ AI ช่วยเชื่อมโยงเคสและร่างรายงาน และต้องมีระบบเก็บ "รง.506" (รายงานผู้ป่วยเฝ้าระวังโรค) ที่เจ้าหน้าที่สอบสวนโรคเป็นผู้สร้างขึ้น โดยแต่ละรายการเลือก "โรคติดต่อ" ได้ (ประเภทโรค) และมีสถานะ "รอพิจารณา" → "ยืนยัน" หรือ "ไม่ยืนยัน" ซึ่งเจ้าหน้าที่สอบสวนโรคเป็นผู้กดเปลี่ยนสถานะเอง |
| ผลกระทบ | ถ้าไม่มีระบบนี้ การยืนยัน/ปฏิเสธเคสเฝ้าระวังโรคยังต้องทำแบบ manual แยกจากระบบ ทำให้ traceability ของการตัดสินใจ (ใครยืนยัน เมื่อไหร่) ไม่ครบถ้วน |
| แหล่งที่มา | รวบรวมจาก ROADMAP.md (คำนำ) + FEATURE-LIST.md บรรทัด Requirement ต้นทาง ของ FEAT-ANALYSIS (`prototypes/v1/case-analysis.html`) + รายละเอียด รง.506 ที่ผู้ใช้ระบุเพิ่มในรอบนี้ (2026-09-06) |

### `PAIN-CONTROL-01` — ต้องการ auto-generate เอกสารขออนุมัติเบิกน้ำมัน/น้ำยาเคมี + แผนปฏิบัติงาน

| หัวข้อ | รายละเอียด |
|---|---|
| กลุ่มผู้ใช้ที่เจอ | ทีมควบคุมโรค/ทีมพ่น |
| ปัญหา | ต้องการ auto-generate เอกสารขออนุมัติเบิกน้ำมัน/น้ำยาเคมี + แผนปฏิบัติงานควบคุมโรค |
| ผลกระทบ | การจัดทำเอกสารขออนุมัติและแผนปฏิบัติงานด้วยมือใช้เวลานาน ทำให้การตอบสนองต่อการควบคุมโรคในพื้นที่ล่าช้า |
| แหล่งที่มา | รวบรวมจาก ROADMAP.md (คำนำ) + FEATURE-LIST.md บรรทัด Requirement ต้นทาง ของ FEAT-CONTROL (`prototypes/v1/control-plan.html`) |

### `PAIN-ASM-01` — ต้องการ AI vision จัดหมวดหมู่รูปภาคสนาม + แจ้งเตือนล่วงหน้าอัตโนมัติผ่าน LINE

| หัวข้อ | รายละเอียด |
|---|---|
| กลุ่มผู้ใช้ที่เจอ | ทีม อสม. |
| ปัญหา | ต้องการ AI vision จัดหมวดหมู่รูปถ่ายภาคสนาม + แจ้งเตือนล่วงหน้าอัตโนมัติผ่าน LINE |
| ผลกระทบ | ปัจจุบันการจัดหมวดหมู่รูปถ่ายภาคสนามและการแจ้งเตือนล่วงหน้ายังต้องทำด้วยมือ ทำให้ อสม. เตรียมพื้นที่ล่วงหน้าไม่ทัน และทีมกลางไม่สามารถติดตามสถานะพ่นแล้ว/ยังไม่พ่นได้แบบ real-time |
| แหล่งที่มา | รวบรวมจาก ROADMAP.md (คำนำ) + FEATURE-LIST.md บรรทัด Requirement ต้นทาง ของ FEAT-ASM (`prototypes/v1/asm-coordination.html`) |

### `PAIN-EXECUTIVE-01` — ต้องการภาพรวมสถานการณ์ระบาดที่ชัดเจน ทันเวลา

| หัวข้อ | รายละเอียด |
|---|---|
| กลุ่มผู้ใช้ที่เจอ | ผู้บริหาร/เจ้าหน้าที่เฝ้าระวัง |
| ปัญหา | ต้องการภาพรวมสถานการณ์ระบาดที่เห็นชัดเจน ทันเวลา แทนการรอรายงานสรุปแบบ manual |
| ผลกระทบ | การรอรายงานสรุปแบบ manual ทำให้ผู้บริหารตัดสินใจช้ากว่าที่ควร และขาดข้อมูลภาพรวม (แนวโน้ม/พื้นที่เสี่ยง) ที่ update ทันเวลาสำหรับวางแผนตอบโต้การระบาด |
| แหล่งที่มา | รวบรวมจาก ROADMAP.md (คำนำ) + FEATURE-LIST.md บรรทัด Requirement ต้นทาง ของ FEAT-DASH (`prototypes/v1/index.html`) และ FEAT-REPORT (`prototypes/v1/reports.html`) |
