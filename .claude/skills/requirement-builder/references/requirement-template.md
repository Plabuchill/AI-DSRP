## หลักการเขียนที่ต้องยึดเสมอ

- **ห้ามเดา pain point ที่ไม่มีคนยืนยัน** — ทุก pain point ต้องมาจากข้อมูลจริงที่ผู้ใช้ระบุ หรือรวบรวมจากเอกสารเดิม (ROADMAP.md/FEATURE-LIST.md) เท่านั้น
- **Traceability** — เชื่อมโยงไป Phase/Feature ID ที่มีอยู่แล้วเท่าที่เป็นไปได้ (ไม่บังคับต้องมีครบ เพราะ REQUIREMENTS.md อาจเขียนก่อน Phase/Feature ID จะถูกกำหนด)
- **เป็นต้นน้ำ ไม่ใช่ปลายน้ำ** — ไม่ต้องอ้างอิงย้อนกลับไปยัง technical design ใดๆ (HIGH-LEVEL-ARCHITECTURE.md ฯลฯ) เอกสารนี้ต้องอ่านได้อิสระจากเอกสารเทคนิค
