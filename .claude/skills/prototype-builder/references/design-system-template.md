# DESIGN.md — แนวทางสร้างและ Template

ไฟล์นี้ใช้ตอน Step 1 ของ `prototype-builder` skill เมื่อยังไม่มี `DESIGN.md` ที่ root โปรเจกต์

## วิธีสัมภาษณ์ผู้ใช้เพื่อสร้าง DESIGN.md

ถามผู้ใช้แบบเปิดกว้างก่อนว่ามีอะไรอยู่แล้วบ้างในมือ (ภาพตัวอย่าง/โลโก้/เว็บที่ชอบ) ถ้าไม่มีอะไรเลย ให้เสนอ 3 แนวทางสไตล์นี้เป็นจุดเริ่ม (ปรับคำอธิบายให้เข้ากับบริบท "AI Disease Surveillance & Response Platform" ซึ่งเป็นระบบสาธารณสุข/เฝ้าระวังโรค):

1. **Clinical / Trustworthy (โทนฟ้า-เขียว, ขาว-เทาอ่อนเป็นพื้นหลัง, ฟอนต์ sans-serif คมชัด)**
   - ข้อดี: ดูน่าเชื่อถือ เหมาะกับหน่วยงานสาธารณสุข/ราชการ, อ่านง่ายสำหรับข้อมูลเชิงตัวเลข/แผนที่
   - ข้อเสีย: อาจดูเรียบ/เป็นทางการเกินไปถ้าผู้ใช้ปลายทางเป็นประชาชนทั่วไปที่ต้องการความเป็นมิตร

2. **Data-dense Dashboard (โทนเข้ม/dark mode, สีเน้น accent สดใสสำหรับกราฟ/แจ้งเตือน)**
   - ข้อดี: เหมาะกับ operator/เจ้าหน้าที่ที่ต้องจ้องหน้าจอนาน เห็น alert/แนวโน้มชัดเจน
   - ข้อเสีย: ไม่เหมาะกับการพรีเซนต์ผู้บริหารหรือ demo กลางแจ้ง/โปรเจกเตอร์

3. **Friendly / Public-facing (โทนสีสดใสขึ้น มุมโค้งมน มี illustration/icon ประกอบ)**
   - ข้อดี: เข้าถึงง่ายสำหรับประชาชน/ผู้ใช้ทั่วไปที่ไม่ใช่เจ้าหน้าที่
   - ข้อเสีย: อาจดูไม่จริงจังพอสำหรับรายงานเชิงนโยบายหรือผู้บริหารระดับสูง

ถามให้ผู้ใช้เลือก 1 ใน 3 หรือผสมกัน หรือถ้ามี hex code / โลโก้ / ตัวอย่างเว็บอยู่แล้ว ให้ใช้สิ่งนั้นแทน
